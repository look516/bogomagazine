- [x] **무결성 가드**: 수집 중인 호에만 업로드, 승인한 조판 버전 기록(수정되면 승인 무효), 승인 후 수정 시 검토로 복귀, `status` 직접 변경 차단

### 설계 점검에서 찾아 고친 문제
- [x] 재오픈하면 배치가 곧바로 다시 닫아 버림 → 재오픈 시 새 마감 시각 필수
- [x] 마감 후에도 사진이 업로드되어 조용히 누락됨 → 업로드 가드 + 행 잠금으로 직렬화
- [x] 낡은 승인이 유효하게 남음 → 승인에 조판 버전 기록
- [x] 조판/승인/인쇄 없이 상태만 끝까지 진행 가능 → 전이 사전조건
- [x] 월초에 모든 그룹이 한꺼번에 마감되면 트랜잭션이 길어짐 → 한 번에 처리하는 양 제한
- [x] 워커가 죽으면 호가 영원히 멈춤 → 임대 + 하트비트
- [x] 같은 시각에 만든 행의 "최신" 판정이 흔들림 → 삽입 순서(`seq`) 기준
- [x] 사용자 기준 조회 인덱스 누락 → 추가
- [x] **Flyway가 `CREATE INDEX CONCURRENTLY`에서 무한 정지** → 재현하고 설정으로 해결 ⚠️ 운영 설정에도 필요([ADR-0002](adr/0002-db-migrations.md))

- [x] **CI 워크플로** 작성: DB 전체 검증 + 마이그레이션 규칙 + 비밀 스캔 ⚠️ 원격에서 아직 실행해 보지 못함

## ⚠️ 알려진 한계 (공유해야 하는 것)

- **아무것도 배포되지 않았다.** 모든 검증은 로컬(Windows + Docker, PostgreSQL 16)에서 했다.
- **GitHub Actions는 원격 실행 전이다.** 문법은 `actionlint`로 확인했다.
- **성능 수치는 합성 데이터와 한 대의 PC 기준**이다(호 1건 조회 약 0.1ms, 마감 200건 약 2.4초). 운영 사양에서는 다르다.
- **운영 배포에도 `FLYWAY_POSTGRESQL_TRANSACTIONAL_LOCK=false`가 필요하다.** 빠뜨리면 인덱스 추가 마이그레이션에서 배포가 멈춘다.
- 모듈 간 **함수/뷰 수준 결합은 자동 검사가 없다.** 외래키 방향만 검사한다([architecture.md](architecture.md)의 "알려진 예외").
- 비밀 스캔은 패턴 기반이라 완벽한 보증이 아니며, 로컬 훅은 `--no-verify`로 우회할 수 있다. `main` 브랜치 보호를 켜야 CI가 실제로 강제된다.
